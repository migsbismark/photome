Metadata records

All dates are shown as yyyy-mm-dd hh:mm:ss in Pacific time (PST/PDT). Dates without a time zone in the file (such as EXIF ModifyDate) are shown as recorded by the camera. Records include every metadata tag returned by ExifTool. Duplicate matching is based on metadata, excluding filesystem-only tags.

Duplicate records

Identical files (same metadata) grouped together: each group has the original, which is its oldest record, and its copies, newest record created first, with a preview of every file. Groups are ordered by their most recent record created (Pacific time). Enter a folder to look only for identical files inside that folder and its sub-folders; leave it empty to look across the whole database. This list is worked out live, so it does not need Find and flag duplicates.

Compare mount points

Which files are in the other mount points but not in the one you choose (the target, the one that should end up complete)? This panel only reads the records: it copies nothing and changes nothing. To bring the missing files over, export the list as CSV, or download a copy script and run it on your PC (it only ever copies; it never overwrites or deletes). Missing files are copied into a _from-<source> folder of the target, keeping their sub-folders. Scan every mount point first.

Sync mount points

Copies the files that other mount points have and the target lacks into the target, so it ends up complete. Files go into <target>/_from-<source>/ (keeping their sub-folders). The sync only adds files: it never overwrites or deletes anything, writes each file under a temporary name first, and checks the size (and, if you tick the box, a checksum) before keeping it. The copies are then scanned into the records, so the target shows as complete in Compare mount points. The target stays read-only except for its _from-<source> folders, which must have been opened for writing on purpose when the app was started (start.ps1 -SyncInto <target>).

Plan a new library

Models how all your files could be stored in a new place: one folder per year, then month, then location, holding the files taken then and there. Duplicates are left out and the original of each is kept. Nothing is copied, moved or changed: this only builds a plan that you can browse and export. The year and month come from the date the camera recorded (or a video's creation date); the location is the nearest town to the GPS position, and files without GPS go to an "Unknown location" folder.

Copy the plan to its new location

Where should the files be copied? Choose a folder on a mount point that is writable (not the archive); the year / month / location folders are created inside it. Originals are only read: nothing is moved, overwritten or deleted, and a file is given its final name only once it has been copied completely. If you run it again, files already there are skipped, so an interrupted copy can simply be continued.
